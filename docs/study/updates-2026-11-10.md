# Updates since 5 November 2026

**Stimulus v2, measurement v2, online operation.** The lab harness has become an online study. The branch
`stimulus-v2-online` is pushed. Each point comes with an example.

## In brief

- The seven user stories are rewritten: with acceptance criteria, an open case at the milestone, and a flaw that
  contradicts exactly one criterion.
  *Example, US1:* "If an item has run out, I am told that it is out of stock (409), not that it does not exist." The
  flaw deletes the item at stock 0, so the next order gets 404.
- Understanding is measured with five questions per feature, each with a role. The question about the open case is
  the milestone item for H1.
  *Example, US6:* How is 15 % of 999 cents rounded? (open case) · Three items at 333 cents with a 10 % coupon
  (dependency) · What does a 100 % coupon do? (flaw) · What happens with an unknown item? (interplay) · What does a
  12.5 % coupon do? (free decision)
- The harness recognises and records when the agent misses the pause, leaves the feature unfinished, or gives a
  design decision away, and catches the last two cases.
  *Example:* The agent wrote "applies the coupon once"; participants read "Step 3: Add the order summary calculator."
- Two complete sessions ran mechanically, one without a browser and one in real Chromium.
  *Example:* The browser run clicked through 7 trials and 49 screenshots to the thank-you page.
- **Conditioner is now part of the deployment path**, the LMU group's platform for online studies with one container
  per participant.
  *Example:* a participant opens `/start/beacon`, Conditioner assigns one of the twelve conditions, starts the pod
  and redirects to `/study/beacon/<user>/`.

## Stimulus

| What | Before | Now | Example |
|---|---|---|---|
| Story | 1–2 sentences | Story with 2–4 acceptance criteria | US6: "A 100 % coupon makes the order free." |
| Open case | was the flaw itself | a separate decision next to the flaw, solved the same in both variants | US1: 5 ordered, 3 left – the whole order is rejected, stock stays at 3 |
| Flaw | partly contestable from the story | contradicts exactly one criterion | US1: item deleted at stock 0 → 404 instead of 409 |
| US3 | a limit could only be lowered | a limit may be raised; the open case is `null` | Tenant sets `maxUsers: null` → the default of 5 applies |
| US4 | no later file built on the milestone | the policy writes durations as text (`"30m"`), the invoice reads them with the parser | Policy threshold `"30"` instead of `"30m"` → generating the invoice fails |

The sheets in `docs/study/stories/` are generated from the trial files so the two cannot drift apart.

## Measurement

- Five items per trial: open case, dependency, flaw, interplay, free decision.
  *Example, US5:* a request exactly at the window boundary · does the client get through after waiting exactly
  Retry-After? · do rejected requests count? · two clients without headers · limit 0.
- Only the open case counts as the milestone item. The dependency question is exploratory because its code is usually
  written after the milestone, and a pause there cannot show it.
  *Example, US1:* the dependency question checks whether `checkout` reports the quantity ordered; step 3 decides that,
  not the milestone in step 2.
- New in the bundle and CSV: `uK_role`, `uK_step`, `uK_milestone`, `featureComplete`, `pauseMissed`.
  *Example:* `u2_role=dependency`, `u2_step=3`, `u2_milestone=false`.
- Exclusions decided in advance: unfinished feature, missed pause.
  *Example:* US2 misses the pause after step 3 → the trial is flagged and excluded, and reported per regime.

## Harness

- **Leak guard:** the agent's text is checked before it is shown. A step announcement that gives a decision away is
  replaced by the neutral step summary; other sentences are removed.
  *Example, US2:* "credit the account from exact integer cents" → "Step 2: Parse the provider's event and credit the
  account in integer cents."
- **Pause nudge:** if the agent stops before the pause, it is sent on with a message the participant does not see, as
  long as no later step has been written.
  *Example:* US2 ends after step 2; the harness sends "You stopped before the feature is finished…", the agent reaches
  the checkpoint in step 3, and the pause happens.
- **Completion nudge:** if files are missing at the end, it is sent on up to twice; after that the trial is flagged.
  *Example:* after the answer "coc" the agent asked again instead of building; the nudge made it write steps 3 and 4,
  and all five items became gradeable.
- **Robust answer scripts:** each module is loaded on its own, so a missing module only costs the items that use it.
  *Example:* if `batch.ts` is missing, the step-2 items stay gradeable instead of all five becoming `null`.
- **UI fixed:** the question list follows the number of items; five questions are shown and submitted.
  *Example:* the page shows "Question 1 of 5", and the server receives five answers instead of four.
- **LiteLLM** no longer stores prompts.
  *Example:* the Drehbuch and participant code no longer land in LiteLLM's Postgres.

## Conditioner

Conditioner runs the study online: one pod per participant, condition assignment, routing under
`/study/<study>/<user>/`, idle stop, browser tracking and the dashboard. Our image provides the pod's content; the
study logic stays in the harness.

| What | State | Example |
|---|---|---|
| Pod per participant | tested in the spike | practice trial through a real browser, plan, pause, terminal, grading, finish |
| Path prefix | works | nginx strips `/study/beacon/<user>/`; the UI adds it back via `base.ts` |
| Conditions | prepared | twelve conditions (6 groups × 2 rounds) through `make-conditions.mjs` |
| Model access | prepared | LiteLLM mints a budgeted key per participant; the provider key stays outside the pod |
| Reprovisioning | untested | resume after a pod restart, multi-pod load |
| Deployment patch | two changes | nginx joins the pods' network; read timeout 30 s → 3600 s |
| Security | open | provisioning and ingest reachable from a pod; no auth or TLS; pod ports on all interfaces |

The two changes to Conditioner are small and documented in `study-harness/deploy/conditioner.patch`; the rest is
configuration (`litellm.yaml`, `conditions.json`). The feedback for the supervisor is in
`docs/harness/conditioner-feedback.md`.

## Decisions

- First sessions online but moderated via Zoom; unmoderated only once the flow is stable.
  *Example:* the pilot participant shares the screen, and the experimenter can restart after a hang.
- N ≈ 30, five per group. For clean cells and more power, 36 would be better.
  *Example:* with 30 people, six of the twelve cells get a third participant; with 36 it is exactly three per cell.
- Hosting by the LMU, testing on the author's own domain.
  *Example:* later `https://study.…` with TLS in front of nginx; testing via the own subdomain.
- Model provider swappable, OpenCode Go for now.
  *Example:* a switch changes only `litellm.yaml`; `study-chat` stays the alias the harness uses.
- A flaw in the milestone step is a clear error next to the open case.
  *Example, US6:* the open case is rounding; the flaw rejects the 100 % coupon.

## Open

- Eval matrix: flaw rate, gradeable items, leaks, spread of the free decision.
  *Example:* 5 runs × 7 stories × 2 variants = 70 runs; target: the flaw lands in ≥ 90 % of Flawed runs.
- Contestability check and a second rater for the milestones.
  *Example:* three people see only the story and decide whether Flawed is an error.
- Authorship of the stories and AI help.
  *Example:* the supervisor asked for stories written by hand; the current ones come from this process.
- Consent, ethics, deception and debrief.
  *Example:* the consent must name the tracker, OpenCode Go and the public plan.
- Conditioner dress rehearsal: TLS, lock the dashboard, egress and API allowlist.
  *Example:* the stack on the test domain, one full session through `/start` rather than `localhost`, and a pod that
  cannot reach `http://provisioning:8180/overview`.
- Before unsupervised operation: resume, collecting volumes, ID linkage, load test.
  *Example:* after 30 minutes idle the pod restarts; the harness must continue where it stopped.
- Re-run power with the pilot's variances.
  *Example:* with an 18-point effect, N = 30 finds it in about 4 of 10 studies.
