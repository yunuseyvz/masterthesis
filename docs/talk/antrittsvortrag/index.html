Problem

Agents write whole features. Developers approve what they barely understand.

Review at the end

14 files changed+ 390 lines✓ 23 tests passed> LGTM, merge

A large diff next to green tests. The tests are taken as proof.

Approval at every edit

edit types.ts? [y]edit types.ts? [y]run npm test? [y]edit route.ts? [y]

Half-written code, many interruptions. People learn to click through.

Both ask for review at the wrong moment. When is the right one?

Knowing Where to Pause2
Idea

Pause at a semantic milestone: the agent just decided something the rest will build on.

Story: “The provider may deliver the same event more than once, and processing can fail temporarily.”

async function processWebhook(log, event, handler) {
  if (log.processed.has(event.id)) return "duplicate";
  await handler(event);
  log.processed.add(event.id);  // only AFTER
  return "processed";
}

A crash between the two lines credits the customer twice. The story never said which way to go.

  1. Open case settledThe story is silent; more than one outcome is reasonable.
  2. Built uponLater code will depend on this decision.
  3. Not yet built uponThat code does not exist yet, so changing course is cheap.

Knowing Where to Pause6
Feedback

Where I would like your input

Control vs. realism

A live agent varies between sessions. Is an instructed, checked agent controlled enough?

Measuring understanding

Multiple-choice questions on behaviour, graded on the real code. Is there a better-grounded instrument?

Sample size

N = 30 only detects a large effect (about 26 points for 80 % power). Accept, or change the design?

Deception

Planted flaws, and a plan on screen that is not the agent's own. Concerns for ethics and the debrief?
