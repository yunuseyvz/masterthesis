3Measures & analysis

One research question: does where the agent pauses affect how well people understand and judge the code?

MeasureRole
4 understanding questions per story (one per step) + confidenceprimary
Accept / reject → fault detection (d′); behaviour question; reversalssecondary
Review time, diff coverage, code on screen, flaw lines seen, terminal and test runsdescriptive
Mental effort, need for cognition, trust in AI, preference rankingcovariates / descriptive
  • H1 (primary): after a pause at the milestone, the question about the milestone step is answered correctly more often than with review at the end (H1a) or a pause elsewhere (H1b).
  • H2: better fault detection at the milestone. H3: a pause elsewhere raises confidence without understanding. H4: reversals after the behaviour question.

4Data collected

Asked directly

  • Consent, age group, programming experience, AI assistant use, code review frequency, TypeScript familiarity
  • Need for cognition (NCS-6) + attention check, trust in AI (S-TIAS)
  • Per story: plan approval, accept / reject, behaviour question, final decision, 4 understanding questions + confidence, mental effort (Paas)
  • At the end: preference ranking, optional comment

Telemetry (automatic)

  • Time per phase and per question, answer changes
  • Changes view open, diff scroll coverage, files opened
  • Code on screen per file and hunk (≥ 1 s = seen), flaw lines seen
  • Terminal commands, test runs and results
  • Focus, idle, chat scrolling, tool expands, clicks
  • Agent events: replayed responses, checkpoints

5Scenario

Participants play a new developer at Shopfront, a small online shop. The product owner writes a user story, the AI agent plans and implements it, and the participant reviews the work before it ships.

  • Accept ships the feature with today's release. Reject sends it back and holds the feature for a day.
  • Afterwards they are on call: a support colleague asks how the new code behaves, without showing it (the understanding quiz).
  • Stakes are framed as real: accepting broken code costs the shop, rejecting good code delays a feature.
  • Not told: the replay, the conditions, the planted flaws. All of it is revealed in the debrief.
